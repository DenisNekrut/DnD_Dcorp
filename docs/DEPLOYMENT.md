# Развёртывание веб-клиента и API

## Веб-клиент

Для сборки фронтенда задайте переменную окружения:

```env
VITE_API_URL=https://api.example.com
```

Указывайте базовый адрес API без завершающего `/api`: клиент самостоятельно добавляет этот префикс.

GitHub Pages размещает только статические файлы фронтенда. Для регистрации, входа и сохранения персонажей отдельно требуется запущенный NestJS API и PostgreSQL.

## API

Скопируйте `apps/api/.env.example` в `.env` на сервере API и заполните реальные значения:

- `DATABASE_URL` — подключение к PostgreSQL;
- `JWT_SECRET` — длинный случайный секрет;
- `WEB_ORIGIN` — точный origin опубликованного фронтенда, например `https://denisnekrut.github.io`;
- `COOKIE_SECURE=true` — обязательно для HTTPS;
- `COOKIE_SAME_SITE=none` — если фронтенд и API размещены на разных сайтах (например, GitHub Pages и отдельный домен API).

Для локальной разработки на одном origin используйте `COOKIE_SECURE=false` и `COOKIE_SAME_SITE=lax`.

При межсайтовом режиме браузер должен разрешать сторонние cookie. API уже включает CORS с credentials и ограничивает origin значением `WEB_ORIGIN`. В production используйте HTTPS для обоих адресов и не ставьте wildcard в CORS.

## Проверка сохранения персонажа

1. Откройте сайт и зарегистрируйте аккаунт.
2. Перейдите в «Персонажи» и создайте героя.
3. Обновите страницу или войдите в аккаунт повторно.
4. Персонаж должен загрузиться из `GET /api/characters/personal`.

Если API недоступен или адрес не задан, приложение покажет сообщение вместо имитации успешного сохранения.


## Администратор портала и модерация

Роль администратора портала не назначается через публичную регистрацию и не может быть выдана из интерфейса обычным пользователем.

1. Зарегистрируйте обычный аккаунт через опубликованный сайт.
2. На сервере API примените актуальную Prisma-схему к PostgreSQL и сгенерируйте клиент:

   ```bash
   cd apps/api
   npx prisma db push
   npx prisma generate
   ```

3. На сервере API назначьте роль существующему аккаунту:

   ```bash
   npm run admin:promote -- your-account@example.com
   ```

4. Выйдите из портала и войдите снова. В боковом меню появится раздел «Администрирование».

Команда назначения роли требует прямого доступа к серверу и переменной `DATABASE_URL`. Не запускайте её с публичного компьютера и не публикуйте строку подключения к базе данных.

### Возможности администратора

- Просмотр списка пользователей и кампаний.
- Просмотр участников любой кампании и последнего сохранённого состояния её игрового стола в режиме только чтения.
- Временная или бессрочная блокировка обычного аккаунта с обязательным указанием причины.
- Снятие блокировки и просмотр журнала действий администраторов.

Блокировка проверяется на сервере при каждом аутентифицированном запросе и при входе, поэтому действующая сессия заблокированного аккаунта теряет доступ к защищённым API. Истёкшая временная блокировка перестаёт действовать автоматически.

Администратор не может заблокировать самого себя или другой администраторский аккаунт. Администраторское наблюдение не предоставляет право редактировать игровое состояние.

### Важно о наблюдении

Сейчас администратор видит последний сохранённый сервером снимок игрового стола и состав участников. Мгновенная трансляция перемещений и событий в реальном времени требует отдельного этапа live-синхронизации и здесь пока не заявляется.


## Временный гостевой режим разработки

Пока API не развёрнут и `VITE_API_URL` не задан, портал предлагает кнопку «Продолжить как гость».

- Гостевые персонажи и кампании сохраняются в `localStorage` текущего браузера.
- Гостевой режим не создаёт серверную учётную запись и не предоставляет роль администратора.
- Гостевые данные не синхронизируются между устройствами, браузерами или аккаунтами.
- Очистка данных сайта/браузера может удалить гостевые данные. Перед очисткой профиля браузера экспорт или перенос данных пока не предусмотрен.
- Общие кампании, заявки, серверное сохранение, межпользовательская синхронизация и модерация требуют работающего API.
- Когда API будет настроен, пользователи смогут войти в аккаунт; локальные гостевые данные останутся в этом браузере и автоматически в аккаунт не объединятся.

Гостевой режим предназначен только для разработки и предварительного тестирования интерфейса. Перед публичным запуском его доступность следует пересмотреть.
