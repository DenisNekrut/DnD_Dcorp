# Развёртывание DnD_Dcorp на Render

## Назначение

Файл `render.yaml` описывает тестовое размещение NestJS API и PostgreSQL в регионе Frankfurt. Blueprint создаёт два ресурса: `dnd-dcorp-api` и `dnd-dcorp-db`.

**Ограничение бесплатной базы:** бесплатный Render Postgres действует 30 дней, имеет ограниченный объём и не предоставляет автоматические резервные копии. Используйте этот вариант только для проверки. Не храните в нём единственную копию важных кампаний и персонажей. Для постоянного использования выберите платный тариф базы и настройте резервное копирование до переноса реальных данных.

## Запуск Blueprint

1. Войдите в Render и откройте создание нового Blueprint.
2. Подключите репозиторий `DenisNekrut/DnD_Dcorp`.
3. Выберите ветку `main`, где находится `render.yaml`.
4. Проверьте план и ресурсы, которые Render собирается создать. Бесплатная база — только временный тест.
5. Подтвердите создание ресурсов.
6. Дождитесь сборки API. Render сам создаст случайный `JWT_SECRET` и передаст API внутренний адрес PostgreSQL через `DATABASE_URL`.
7. Откройте URL созданного Web Service и проверьте `/api/health`. Ответ должен содержать `status: "ok"` и `database: "connected"`.

Не публикуйте значения `DATABASE_URL` или `JWT_SECRET`, не добавляйте их в Git и не отправляйте в чат.

## Применение схемы базы

Для тестового Blueprint используется команда `npm run start:render`: перед запуском NestJS она выполняет `prisma db push --skip-generate`. Это нужно, потому что новая база изначально пустая, а бесплатный план Render не предоставляет pre-deploy command.

Это временный механизм для разработки. Он запускается при каждом старте контейнера и не заменяет версионируемые миграции. Перед эксплуатацией с важными данными необходимо перейти на Prisma Migrate, выполнять миграции отдельным pre-deploy шагом и проверять их на резервной копии.

## Подключение GitHub Pages

После успешного запуска скопируйте публичный URL API из Render, например `https://<имя-сервиса>.onrender.com` (без завершающего `/api`).

В GitHub откройте репозиторий → Settings → Secrets and variables → Actions → Variables и создайте переменную:

- Name: `VITE_API_URL`
- Value: публичный URL API из Render, без завершающего `/api`.

Затем запустите workflow **Deploy web preview** через Actions → Run workflow либо отправьте новый commit в `main`. Сборка фронтенда прочитает эту переменную и включит адрес API.

Если переменная не задана, сайт останется в гостевом режиме. Секреты API не нужно помещать в frontend variables: `VITE_API_URL` — публичный адрес, а не ключ доступа.

## Проверка после подключения

1. Откройте `https://denisnekrut.github.io/DnD_Dcorp/`.
2. Зарегистрируйте тестовый аккаунт.
3. Создайте личного персонажа и обновите страницу.
4. Создайте кампанию и проверьте её сохранение.
5. Откройте игровой стол и проверьте сохранение изменений после обновления страницы.
6. Проверьте API health endpoint отдельно.

### Межсайтовые cookie

GitHub Pages и адрес `onrender.com` относятся к разным сайтам. API настроен на HTTPS cookie с `SameSite=None` и credentialed CORS, но браузеры могут блокировать сторонние cookie. Если регистрация или вход не сохраняют сессию, это может быть ограничением браузера, а не ошибкой пароля.

Для надёжного публичного запуска рекомендуется собственный домен и единый сайт для фронтенда и API (например, проксирование `/api` через тот же origin). До этого межсайтовая авторизация не гарантируется во всех браузерах.
