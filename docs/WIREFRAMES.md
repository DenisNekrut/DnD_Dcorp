# Wireframes DnD_Dcorp — черновые макеты

## 1. Назначение

Документ описывает низкодетализированные wireframe-макеты основных экранов. Это схема расположения элементов и поведения интерфейса, а не окончательный визуальный дизайн. Все игровые правила соответствуют D&D 5e.

## 2. Общая оболочка личного кабинета

На десктопе используется постоянная боковая навигация и рабочая область.

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ЛОГО DnD_Dcorp                         Уведомления   Профиль         │
├───────────────┬─────────────────────────────────────────────────────┤
│ Главная       │ Заголовок текущего раздела                           │
│ Кампании      │                                                     │
│ Персонажи     │ Основное содержимое                                  │
│ Библиотека    │                                                     │
│ Настройки     │                                                     │
│               │                                                     │
│               │                                                     │
└───────────────┴─────────────────────────────────────────────────────┘
```

На узких экранах боковая навигация сворачивается в компактное меню. Игровой стол проектируется отдельно и не обязан сохранять эту оболочку.

## 3. Экран 1 — личный кабинет

### Компоновка

```text
┌─────────────────────────────────────────────────────────────────────┐
│ Главная панель                                      [Создать кампанию]│
├─────────────────────────────────────────────────────────────────────┤
│ Добро пожаловать                                                    │
│ [Продолжить последнюю игру]  [Найти кампанию]  [Создать персонажа]   │
├────────────────────────────────┬────────────────────────────────────┤
│ МОИ КАМПАНИИ                   │ УВЕДОМЛЕНИЯ                        │
│ ┌────────────────────────────┐ │ ┌────────────────────────────────┐ │
│ │ Название кампании          │ │ │ Приглашение / заявка            │ │
│ │ Роль • статус              │ │ │ Системное событие               │ │
│ │ [Открыть]                  │ │ └────────────────────────────────┘ │
│ └────────────────────────────┘ │                                    │
│ ┌────────────────────────────┐ │ БЫСТРЫЕ ССЫЛКИ                    │
│ │ Следующая кампания         │ │ [Мои персонажи] [Библиотека]       │
│ └────────────────────────────┘ │                                    │
└────────────────────────────────┴────────────────────────────────────┘
```

### Поведение
- Кнопка продолжения появляется, если у пользователя есть доступная активная сессия.
- Карточка кампании показывает название, роль и состояние кампании.
- Уведомления ведут к соответствующей заявке, приглашению или событию.
- Действия создания доступны с учётом прав и состояния аккаунта.

## 4. Экран 2 — страница кампании

### Компоновка

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ← Кампании     НАЗВАНИЕ КАМПАНИИ                    [В игровой стол] │
├─────────────────────────────────────────────────────────────────────┤
│ Обзор | Участники | Заявки | Сцены | Журнал | Настройки              │
├─────────────────────────────────────────────────────────────────────┤
│ Краткое описание кампании                                            │
│ Статус: активна / подготовка / завершена                             │
├────────────────────────────────┬────────────────────────────────────┤
│ УЧАСТНИКИ                      │ ПРИГЛАШЕНИЯ И ЗАЯВКИ                │
│ Мастер                         │ Ожидающие заявки                   │
│ Игроки                         │ [Одобрить] [Отклонить]             │
│ Помощники                      │                                    │
│ Наблюдатели                    │ [Скопировать ссылку приглашения]   │
├────────────────────────────────┴────────────────────────────────────┤
│ Последние события / журнал                                           │
└─────────────────────────────────────────────────────────────────────┘
```

### Поведение
- Вкладки и действия отображаются в зависимости от роли.
- Мастер управляет приёмом заявок, участниками, паролем и приглашениями.
- Помощник видит только те инструменты, на которые ему выданы разрешения.
- Игрок видит доступную ему информацию о кампании и участниках.
- Перед входом в игровой стол сервер повторно проверяет членство и права.

## 5. Экран 3 — лист персонажа

Лист разделён на логические вкладки, чтобы не перегружать один экран. Основные показатели D&D 5e остаются быстро доступными.

### Компоновка

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ← Персонажи     ИМЯ ПЕРСОНАЖА                   [Сохранить] [Меню]   │
├─────────────────────────────────────────────────────────────────────┤
│ Уровень | Класс | Предыстория | Вид/раса | Мировоззрение             │
├─────────────────────────────────────────────────────────────────────┤
│ ХАРАКТЕРИСТИКИ     │ БОЕВЫЕ ПОКАЗАТЕЛИ                              │
│ Сила               │ Класс доспеха                                  │
│ Ловкость           │ Инициатива                                     │
│ Телосложение       │ Скорость                                       │
│ Интеллект          │ Максимум хитов / текущие хиты / временные хиты │
│ Мудрость           │ Кость хитов                                    │
│ Харизма            │ Спасброски от смерти                           │
├────────────────────┴────────────────────────────────────────────────┤
│ Вкладки: Обзор | Навыки | Снаряжение | Заклинания | Черты | Заметки │
├─────────────────────────────────────────────────────────────────────┤
│ Содержимое выбранной вкладки                                        │
└─────────────────────────────────────────────────────────────────────┘
```

### Принципы
- Значения и бонусы вычисляются по правилам D&D 5e; производные поля не должны произвольно редактироваться.
- Броски характеристик, навыков и спасбросков доступны из листа и передают результат в игровой журнал.
- Учитываются владения, бонус мастерства, преимущества и помехи, состояния и эффекты, предусмотренные правилами.
- Состав полей и доступность редактирования зависят от этапа создания персонажа, уровня и выбранных опций D&D 5e.
- Личная карточка и сессионная копия персонажа визуально помечаются разными статусами.

## 6. Экран 4 — игровой стол

### Компоновка

```text
┌─────────────────────────────────────────────────────────────────────┐
│ Кампания / Сцена       Инструменты карты      [Настройки] [Выход]    │
├───────────────┬───────────────────────────────────┬─────────────────┤
│ УЧАСТНИКИ     │                                   │ ПЕРСОНАЖ        │
│               │                                   │                 │
│ Мастер        │          ИГРОВАЯ КАРТА            │ Имя             │
│ Игрок 1       │                                   │ КД / Хиты       │
│ Игрок 2       │       Фигуры / объекты            │ Скорость        │
│ Наблюдатель   │       Сетка / сцена               │ Действия        │
│               │                                   │                 │
├───────────────┴───────────────────────────────────┴─────────────────┤
│ ЧАТ                 │ ЖУРНАЛ БРОСКОВ / СОБЫТИЙ                      │
│ Сообщение... [Отпр.]│ d20  • Проверка навыка • Результат             │
└─────────────────────────────────────────────────────────────────────┘
```

### Поведение
- Центральная карта получает максимум доступного пространства.
- Боковые панели можно сворачивать и менять ширину.
- Игрок управляет только разрешёнными ему фигурами и объектами.
- Мастер получает инструменты сцены, видимости, скрытых объектов и управления встречей.
- Наблюдатель не получает управляющих действий.
- Броски и важные изменения состояния синхронизируются с сервером и журналом.
- Скрытые от игроков сведения не должны попадать в клиентские данные игрока до раскрытия.

## 7. Состояния и обратная связь

Для всех экранов предусмотреть:
- загрузку;
- пустое состояние с понятным следующим действием;
- ошибку и повтор операции;
- подтверждение опасных или необратимых действий;
- отсутствие доступа;
- сохранение и несохранённые изменения;
- отключение и восстановление соединения;
- адаптивное отображение на узких экранах.

## 8. Приоритеты дальнейшего UI-проектирования

1. Утвердить общую сетку, типографику, цветовые токены и набор компонентов.
2. Детализировать лист персонажа и создание персонажа по D&D 5e.
3. Детализировать игровой стол: карта, панели, чат, журнал и режимы мастера.
4. Подготовить кликабельные состояния и сценарии взаимодействия.
5. Перейти к реализации frontend.

## 9. Ограничения

Wireframes не заменяют техническую спецификацию, серверную модель разрешений или правила D&D 5e. Все операции и игровые вычисления должны быть подтверждены сервером; интерфейс не является доверенной средой.
